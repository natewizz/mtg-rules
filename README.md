# mtg-rules

`mtg-rules` is a small open-source developer utility that turns the official Magic: The Gathering Comprehensive Rules TXT published by Wizards of the Coast into trustworthy, structured, machine-readable data.

## Version

This repository currently implements **v0.1.1**.

The v0.1 promise is:

> Given an official Wizards Comprehensive Rules TXT file, reliably parse it into structured JSON with stable rule IDs and validate that no meaningful source content was silently lost.

v0.1.1 is a hardening release. It centralizes rule-ID handling, adds structured diagnostics, provides a source-health `doctor` command, supports local hash-based diffs, improves source discovery checks, and verifies packed npm consumers.

## Licensing and source-data policy

The complete Comprehensive Rules text is copyrighted by Wizards of the Coast. Until explicit redistribution permission is received, this repository does **not** contain:

- the official Wizards TXT file;
- generated JSON containing the complete official rules text; or
- a bundled copy or mirror of the source data.

The CLI fetches the current TXT from the official Wizards rules page, or accepts a local file supplied by the user. Fetched source and generated output should remain local. Synthetic fixtures in `tests/fixtures/` are original test material.

Local `diff` operates on documents supplied or generated by the user. It reports rule IDs and hashes by default and does not create a hosted historical archive.

## CLI

Fetch the current official source. This writes only to the path you choose:

```bash
npx tsx src/cli.ts fetch -o /tmp/MagicCompRules.txt
```

Parse a local source file into deterministic JSON. Keep the output local:

```bash
npx tsx src/cli.ts parse /tmp/MagicCompRules.txt -o /tmp/rules.json
```

Validate a source file for unclassified content and structural errors:

```bash
npx tsx src/cli.ts validate /tmp/MagicCompRules.txt
```

Print machine-readable validation output:

```bash
npx tsx src/cli.ts validate /tmp/MagicCompRules.txt --json
```

Run a source health check:

```bash
npx tsx src/cli.ts doctor /tmp/MagicCompRules.txt
npx tsx src/cli.ts doctor /tmp/MagicCompRules.txt --json
```

Inspect a rule from local generated JSON:

```bash
npx tsx src/cli.ts rule 704.5f --from /tmp/rules.json
```

Diff two local generated JSON documents:

```bash
npx tsx src/cli.ts diff /tmp/old-rules.json /tmp/new-rules.json
npx tsx src/cli.ts diff /tmp/old-rules.json /tmp/new-rules.json --json
```

Human-readable diffs show added (`+`), changed (`~`), and removed (`-`) rule IDs. JSON diffs contain deterministic ID lists and, when present, provenance. Rule text is not copied into the diff result.

After building, the CLI is also available as:

```bash
npm run build
node dist/cli.js --version
```

## Programmatic API

```ts
import { diffRules, getRule, parseRules, validateRules } from 'mtg-rules';

const document = parseRules(sourceText, {
  sourceUrl: 'https://media.wizards.com/.../MagicCompRules.txt',
});

const report = validateRules(document);
const rule = getRule(document, '704.5f');
const changes = diffRules(oldDocument, document);
```

The public API also exports `isRuleId`, `parseRuleId`, `parentRuleId`, `compareRuleIds`, `fetchRules`, `discoverRulesUrl`, `discoverRulesUrlFromHtml`, and `stringifyRules`.

## Rule IDs

Wizards rule numbers are the canonical identifiers. They remain exact strings such as:

```text
100
100.1
100.1a
704.5
704.5f
903.10
```

The shared rule-ID utility provides validation, parsing, parent lookup, and canonical ordering. Rule renumbering is represented as a removal plus an addition; the project does not infer semantic identity across different IDs.

## Parser and validation guarantees

The parser is deliberately conservative. It handles the observed official document regions:

- effective-date metadata and introduction;
- contents/navigation material;
- numbered sections and numbered rules;
- lettered subrules and multiline continuations;
- `Example:` blocks, including consecutive examples;
- glossary entries and multiline definitions; and
- credits/legal end matter.

Whitespace normalization includes non-breaking spaces used on blank lines, Unicode line separators present inside some source paragraphs, BOMs, CRLF input, and missing final newlines.

Every source line is classified. Unknown meaningful lines are reported as stable structured diagnostics rather than silently dropped. Diagnostics include machine-readable codes such as `UNCLASSIFIED_LINE`, `DUPLICATE_RULE_ID`, `INVALID_RULE_ID`, `ORPHAN_RULE`, and `MISSING_EFFECTIVE_DATE`.

Validation checks effective date, rule ID shape, duplicate IDs, parent relationships, sections, glossary, credits, ordering warnings, and unclassified meaningful lines. The normal CLI remains human-readable; `validate --json` returns deterministic JSON with `valid`, `errors`, `warnings`, and `stats`.

## Provenance and deterministic output

Generated documents may include:

- effective date;
- official source URL;
- source SHA-256; and
- a `wizards-of-the-coast` / `magic-comprehensive-rules` provenance object.

No volatile retrieval timestamp is added to canonical output. Parsing and serializing the same source produces byte-for-byte identical JSON. Rules include SHA-256 hashes of their normalized rule text.

## Local diffs

`diffRules(oldDocument, newDocument)` classifies rules as:

- **added** — ID exists only in the new document;
- **removed** — ID exists only in the old document;
- **changed** — ID exists in both documents but hashes differ; and
- **unchanged** — ID exists in both documents and hashes match.

No semantic rename detection is attempted. A renumbered rule is removed and added.

## Integration test

The live Wizards integration test is opt-in so ordinary test runs do not depend on the network:

```bash
MTG_RULES_INTEGRATION=1 npm test
```

Or use a previously downloaded local source:

```bash
MTG_RULES_SOURCE=/tmp/MagicCompRules.txt npm test
```

If Wizards changes the source format and the parser no longer understands it, the integration test is expected to fail until the parser is updated.

## Architecture decisions

Short decision records are in `docs/decisions/`:

- rule numbers are canonical identifiers;
- generated output is deterministic; and
- rules text is not semantically interpreted.

## v0.1 non-goals

This version does not provide historical storage, a hosted archive, a website, an HTTP API, React components, semantic interpretation, card interaction logic, keyword semantics, AI features, npm publishing, or automatic update releases.
